## 一、游戏做成什么样：一句话定位

**「可以行走的《选佛谱》」**——蕅益大师的十五门二百二十位是骨架，须弥山十法界世界地图是血肉，
敦煌经变画是衣裳。玩家掷轮行谱，每一位不再是表格上的格子，而是世界中的一处；
每到一处，谱曰原文与经证展开——「即遊戲間，頓知六道往還之疲苦，三乘出要之差別」。

### 三层游戏结构（与工程三层构架对齐）

| 层 | 内容 | 依据 |
|---|---|---|
| 行棋层 | 选佛谱本体：二轮掷六字、十五门220位升沉、赠掷、圆满 | B0136 已双录互证的数据与引擎（G 版 positions.json + 21 单测，直接延用） |
| 世界层 | 须弥山十法界地图：落位即落在世界某处，跨界迁移走光路 | 本工程 world.json（96 条经证全绿） |
| 闻思层 | 谱曰全文＋白话辅读＋经证卡＋众生相经幢 | 核证管线（verify-claims 体例） |

### 核心循环（一掷之内的完整体验）

```
掷轮（双轮旋掷，轮相非骰具，恭敬呈现）
  → 判词（谱曰摘句，繁体原文＋可展开白话）
  → 迁移（光路飞移：升则登高、堕则沉降；特殊通道有专属演出——
          阿鼻蒙光径生兜率的「慈光通道」、诸位佛佛横超西方的「横超光路」，皆有谱曰/经文依据）
  → 落位开卷（新场景以横卷从右向左展开——中国手卷的阅读方向）
  → 可选探索（游卷、点热区读经证、看众生相）
  → 交轮（多人时轮转下一位莲友）
```

## 二、交互建议（重点）

### 1. 三种视图，一键互切

- **谱图**（立轴总览）：即本工程已做的立轴地图——看全局、看自己与莲友在十法界中的位置；
- **行谱**（对局主界面）：掷轮＋判词＋行谱录，信息密度最高，手机单手可玩；
- **卷轴**（场景探索）：落位后进入该处的敦煌式横卷，横向滑动游览，点位读经证。

三视图共读同一份 world.json 与谱位数据，不做三套数据。

### 2. 掷轮的仪式感

拖拽旋掷（触屏划动给初速），轮停显相，六字「那謨阿彌陀佛」逐字亮起；
掷前轻声木鱼、掷中古琴泛音、落定念佛声（音声资产走 R2）。
**不做赌具化演出**（不弹金币、不抖屏）——轮相是念佛之相，这是既定家法。

### 3. 卷轴探索 = 「可读的经变画」

这是把发起人「还原25窟净土变、交互探索」的构想与本工程核证管线接起来的关键：

- 每幅还原场景中的**可点热区，都挂一条已核经文**。以榆林窟25窟观无量寿经变为例：
  中央说法会→《观经》相应段、宝池莲花童子→第五池观／九品生想、虚空楼阁→楼观、
  两侧条幅→未生怨与十六观次第——**T0365 观经全文已在本库语料中，逐热区逐字核证完全可行**；
- 探索不设收集/积分（无积分排行是既定纪律），探索的回报就是「看见经文所说」；
- 圆满时刻的安置：当玩家行至第十四门净土横超（往生诸位），**才**进入极乐净土变全卷——
  把最重的美术资产放在法义最重的时刻，游戏节奏与教理同构。

### 4. 强烈建议：主视觉走 2.5D「可行走的经变画」，不走全 3D

理由：
1. **风格保真**：敦煌壁画是平面艺术，分层长卷（近/中/远景视差）能原样保留矿物色与线描质感；
   全 3D 需要把画「翻模」，历次尝试证明几何体与壁画质感之间总有断裂；
2. **素材管线匹配**：higgsfield 产出的是**画**（图/视频），直接切层入卷即用；产 3D 模型则做不到；
3. **性能与体积**：手机 H5 首屏小、帧率稳；3D 的 LOD/流式加载工程量大；
4. **已验证的地基**：立轴地图本身就是 2.5D 谱图，风格天然连续。

3D 不废弃：立轴地图与坛城总览可作 3D 化的远期方向（读同一 world.json），但**不挡首发**。

### 5. 单人「独修」与多人「共修」

- 单人：完整全流程，存续局；
- 多人：房号制至多四人共修＋聊天（复刻版的 Cloudflare Durable Object 联机代码整体可迁移），
  **赠掷**沿用 G 版定夺（赠掷＝赠他人行，法布施的游戏化）；
- 轻社交，无排行榜、无对抗计分——共修不是竞技。

## 三、higgsfield 接入：离线素材管线（不做实时生成）

### 定位

higgsfield 用于**制作期出图/出动效**，产物经人工审校后作为静态资产入库——
不在运行时调用（成本、延迟、风格漂移、内容风险四个原因，缺一不可）。

### 管线（与白话辅读管线同纪律：AI 起草 → 人工核证 → 仅 verified 入库）

```
① 底稿：数字敦煌开放素材（公益授权通道）＋ 发起人自备高清图（榆林25窟观经变、莫高112窟等）
② 生成：higgsfield 图生图/风格参考——按「层」出图（天空层/建筑层/主尊层/宝池层/前景装饰层），
        每层单独出，方便切视差与热区
③ 审校（人工，逐张）：a. 恭敬与如法——佛菩萨形象依 07-11 定夺（心存恭敬＋敦煌白描底稿再创作）；
        手印、持物、方位、胁侍位次不可错，对照底稿与经文核；b. 风格一致性——矿物色谱系统一
④ 入库：assets/ 按 world.json 节点 id 归档，附来源记录（底稿出处＋生成参数），热区表挂经文 ref
⑤ 动效：higgsfield 的视频能力用于转场演出（莲花开合、宝楼光云、横超光路），
        输出序列帧或短视频贴片，不做实时渲染
```

## 四、工程路线：网页版 → GitHub → Cloudflare →（远期）Steam/App Store

### 架构（沿用已验证的模式）

- **单仓**：world-model（数据+核证，已有）＋ game（Vite 前端）＋ worker（Cloudflare Worker + Durable Object 联机，迁移自复刻版）；
- **部署**：静态 dist 与联机 API 同一 Worker，`npm run deploy` 一步（复刻版模式原样可用）；
  GitHub Actions push main 自动部署（foyue/wenchao 已跑通的流程）；
- **大资产走 R2**：经变画分层图、音声（古琴/佛号）——图片 AVIF/WebP 双格式，按卷懒加载，首屏 <3MB；
- **PWA**：手机可安装、离线可玩单人局（存续局在本机）。

### 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| M0 网页版 MVP | 行棋层＋谱图接通：掷轮→判词→立轴地图落位→经证卡；纯静态可部署 | 无头模拟整局全圆满；手机实机全流程 |
| M1 第一卷 | 卷轴视图＋两卷内容：南赡部洲起手卷＋极乐净土变卷（发起人素材） | 热区经文逐条已核；30fps |
| M2 共修上线 | DO 联机迁移＋Cloudflare 部署＋GitHub Actions | 四人房实测；域名接入 |
| M3 全量内容 | 众生相经幢、音声、PWA、白话辅读全量 | 引文核证全绿；离线单人可玩 |
| M4 上架壳 | Steam＝Tauri 壳（比 Electron 轻）；iOS＝Capacitor 壳 | 见下方注意项 |

### 上架注意（远期，先记录）

- **Steam**：全球区无需版号（国区页面另论）；Tauri 打包体积小；成就/云存档可后置；
- **App Store**：无内购则审核路径最短；宗教内容以「文化/教育」定位陈述；
  中国大陆区对宗教类 App 有额外资质要求——**建议先上海外与港台区**；
- 两平台都要求素材版权可自证——即第三节的链路留痕。
