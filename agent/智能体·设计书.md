## 二 · 不變的：接口契約

前端 `十法界须弥山世界/src/game.js` 已依此契約寫成，**新智能體照此實現，前端零改動**。

**請求**（`POST /v1/ask`，經遊戲 Worker 之 service binding 轉發）

```json
{ "question": "…", "pos": "圓五品位", "posName": "圓五品觀行位",
  "door": 13, "doorTitle": "圓教位次門",
  "combo": "阿彌", "n": 7, "trail": ["發始因地", "聽法", "五戒"] }
```

**回應**

```json
{ "requestId": "…",
  "answer": "…含 [n] 標記…",
  "citations": [{ "index":1, "id":"…", "sourceId":"B0136", "title":"…",
                  "ref":"《選佛譜》卷第六・初發心住・L57", "url":"…CBETA…",
                  "quote":"逐字原文", "supports":"…" }],
  "boundaries": ["…本答語所據之範圍…"],
  "basis": { "mode":"…", "label":"…" },
  "evidenceStatus": "grounded | ungrounded | refused",
  "remaining": 99, "cacheStatus": "hit | miss" }
```

> 舊實現對拒答也報 `evidenceStatus: grounded`、對不相干引文也照掛——新實現須令此欄真正有判別力。

## 四 · 樞紐是「位」，不是四個並列的庫

用戶問的四類——**這步棋為什麼／輪相說明什麼／修行知識／十法界知識**——現在之所以「沒發揮作用」，是因為它們在系統裡是並列的。它們本是一體，樞紐是**位**。

一個位（如「初發心住」）同時繫著：

```
                    【初發心住 g12-11】
                            │
    ┌─────────┬─────────────┼─────────────┬─────────┐
  21格承注   位譜曰全文    所屬門次第    所錨法界     上下位
   L0        ＋白話 L1      L1          節點 L2      次第
  這步棋      這位是什麼    修行知識     十法界      我從哪來
  為什麼                                            能到哪去
                            │
                      六字表法 L3
                     輪相說明什麼
```

### 修行知識不必另建庫——十五門本身就是

- **門六 生善滅惡**：聽法・護法・請法 ＋ 作法／取相／無生三懺（行法）
- **門七 增上戒學**：五戒→八戒→十戒→比丘律→二部律→廣持→住毗尼→善滅諍→大乘五支淨戒（十三位即完整戒學次第）
- **門八 增上定學**：六妙門→十六特勝→通明觀→九想→八念→十想→八背捨→八勝處→十一切處→九次第定→師子奮迅→超越→王三昧
- **門九 增上慧學**：六種發心與觀門

**門八的譜曰是全譜篇幅之最，因為它逐一寫了每種禪法怎麼修**——六妙門的數隨止觀還淨六步、十六特勝的十六法逐條對治、九想觀的九想次第、八背捨從觀左足大拇指起的完整觀法。這本來就是一部修行手冊，只是現在沒有以「修行」這個視角被索引。

```
問句
 ├─ ① 定本路由（零 LLM）
 │    位×相 → L0 查表 → 直出 {verdict, 答, 引}
 │    觸發：帶 pos+combo 之請求（「AI 解讀」按鈕）、或問句可解析出位相
 │    覆蓋：遊戲內提問之大宗。零延遲、零幻覺
 │
 ├─ ② 據文路由（LLM 只做組織）
 │    實體匹配 → L1/L2/L3 取材 → 接地作答 → 逐句掛 [n]
 │    觸發：位問、門問、界問、相問、修行問
 │
 ├─ ③ 串講路由（LLM 做組織與對比）
 │    多實體取材 → 綜合 → 逐句掛 [n]
 │    觸發：跨門對比（「別教和圓教的三惡相為什麼不一樣」）、次第串講
 │
 └─ ④ 拒答路由（定句，不調生成）
      譜外實修、吉凶、個人決斷、零命中、檢索故障
```

路由判定用輕量規則 ＋ 一次小模型分類，**不用大模型**。

## 六 · 三道紀律

### 紀律一 · 斷言級引文核驗（治問題 1）

舊版只校驗帶引號的直引。**新版須把答語中的數字、年號、位名、門號一併回查**——凡此四類 token 不能在所引段落裡逐字找到，即剝除或降級為「未見明文」。

> 實測那句「萬歷己巳年（1599年）…1368字」正是**無引號的裸陳述**，舊版檢不出。

### 紀律二 · 零命中直接拒答（治問題 3）

檢索故障 → 據實告知「檢索服務暫時不可用」，**絕不誣為「未見明文」**；
檢索正常但零命中 → 直接拒答，**不調用生成模型**（省算力，且從機制上杜絕無據發揮）。

`evidenceStatus` 三值須真正有判別力：`grounded`（引文支持答語）／`ungrounded`（有引文但不足支持）／`refused`（拒答，不掛引文）。

### 紀律三 · 分級標示不混同（治問題 4 及全譜體例）

- 逐字引文、專案釋義、操作規則**不得互相冒充**（前端 `SFP_EVIDENCE_TYPE` 已立此則，沿用其欄位名，不新造）
- 繁簡**一律跟隨用戶設置**——遊戲設定裡那一個 OpenCC 開關統管全站，答語與引文同轉，不另立規矩。
  數據層則統一存底本形（繁）：存繁存簡本不影響顯示，但統一之後核驗方能同形嚴格逐字比（見 §十二·統一底本形）。
  用戶若要核底本原貌，點出處卡上的 CBETA 鏈接
- 拒答一律中文，**不洩漏內部欄位名**

## 七 · 渲染：NotebookLM 式，角標即出處

```
九法王子住 · 擲得「那那」→ 不行
那那所須者無生懺，即觀罪實相[1]；七不退住已入無生畢竟空界而名不退[2]，
所觀既成，則不復須懺。故那那自七不退住以上不行。
  [1] 《選佛譜》卷第六・初發心住・L57
      「是故六住已前。煩惑未盡。猶得有退轉義。那那須修無生懺也。」
  [2] 《選佛譜》卷第六・七不退住・L81
      「入於無生畢竟空界。名不退住。准位應同阿羅漢果。已辦地也。」
```

**角標一律用數字，不加類型標籤，不加免責句。** 出處本身把分量說盡了——引的是本位還是他位、一條還是三條，點開一看便知。`level`（直說／承注／攜帶／通則／推演）**只供審計與校驗，不出前臺**。

#### 全鏈路

```
問句 → 意圖理解（模型在輸入端，失敗降級正則）
     ├─ 位×相 → 承注庫 4620 格，逐字引文，可跳位      ttft 0.1 ms
```

#### 線上驗證揪出兩件本地評測沒抓到的

**一、問文庫之 delta 未解物件。** 佛樂送 `{"text":"…"}`，本譜只解字串，吐給用戶的遂是一串 JSON。
本地評測只驗 `basis.mode` 而不驗文本，故漏到線上。**評測已補文本檢查。**

**二、接檢索層時路由順序放錯。** 譜內檢索搶在旁路與個人決斷之前——
