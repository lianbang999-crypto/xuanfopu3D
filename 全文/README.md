# 《選佛譜》全文錄入工程

承注庫管的是 4620 格「某位擲某相如何走」；本工程管的是**全書其餘一切**——
序、卷首〈輪相表法第一〉、〈位次升降第二〉、十五門總說、二百二十位譜曰、卷末。

## 為何要手工

全書七萬四千餘字，機械切塊必壞語義。實例：底本第 33 行是**一整行 1238 字，內含四則問答**——

> 問。何意不用幺二三四五六…故用此六字為輪相也。　問。那謨。此翻歸命。亦應是善。何得表惡…

每一則問答都是一個**天然的檢索單元**：用戶問「為什麼用那謨阿彌陀佛六字」，就該命中第一則。
按字數切會把它們切散，按行切則四則糊成一塊——兩者皆不堪用。

## 錨句法：語義邊界人工定，逐字原文機器取

塊只記**邊界與義理提要**，不抄原文：

```json
{
  "id": "j1-qa-01",
  "juan": 1, "line": 33,
  "sec": "輪相表法第一",
  "kind": "qa",
  "title": "何意不用幺二三四五六，乃用那謨阿彌陀佛六字",
  "from": "問。何意不用幺二三四五六",
  "to": "故用此六字為輪相也。",
  "terms": ["萬德洪名", "無記法", "不退轉"]
}
```

`build.mjs` 依 `line` 取底本該行，自 `from` 起至 `to` 止取出原文。

**分塊準確靠人，逐字準確靠機器**——與承注庫同一體例（規則人工核定，展開機械執行）。

## 三道校驗（build.mjs，皆須零）

| | |
|---|---|
| ① 錨句可尋 | `from`／`to` 須在該行逐字尋得，且 `to` 在 `from` 之後 |
| ② 塊不重疊 | 同一行內諸塊之區間不得相交 |
| ③ **覆蓋率** | 諸塊所取原文，須覆蓋底本全文（除 CBETA 頭部、圖片標記、校勘記）。**這是「全部錄入」的可驗證保證**——有一段沒錄入，覆蓋率即掉 |

## 為何不建向量庫

全書切完約六百餘塊、一百八十餘 KB——比佛樂問文庫（8999 塊）少一個數量級，
可整個打進 Worker bundle，檢索在內存裡做。

且本譜有比向量更準的東西：**結構化實體表**（220 位 ＋ 15 門 ＋ 291 詞條 ＋ 55 法界節點，皆有別名）。
問「見惑」直接命中詞條，問「初住」別名表命中位——精確匹配勝於向量之概率召回。

向量庫待兩事之一乃考慮：語料漲至數千塊（如真接蕅益四部），或評測顯示倒排召回不足。
屆時再上，且有 baseline 可比。

### 校驗途中揪出的錯，皆非機器可代

1. 三處 `table` 止錨自他位誤抄（根本四禪寫成「佛佛。出世慧學)」，實為「佛佛。圓十信)」）
2. 四處細分塊之 `to` 用了下段之首 → 區間相交
3. 見取、世間福之自動邊界切在句中
4. 卷一卷題、卷六三等一切佛迴向譜曰漏錄——**覆蓋率報「未錄入 N 行」方才發現**
5. 卷六校勘記佔行，致譜曰行號偏移二處

第 4 條尤見覆蓋率之用：漏一行它就報，不靠人記性。

### 全書要處之錨點（此前散在承注庫作引文碎片，今有完整上下文）

- **敘**：「未有不達法門中事輙敢師心自創立者」「皆本教乘非出臆見」——作譜之立場
- **輪相表法**：那謨表見愛二惑、阿彌陀佛表施戒定慧四善、有漏無漏、生滅等四門
- **見取三問答**：相雜六相通則之出處（「其餘位中。以阿彌陀善。與那謨惡相為對治」）
- **無生懺**：「先用作法取相而導其流。隨即觀罪性空以塞其源」
- **福生天**：「未得上地定力。不能越色界故」——散善止於色界之根據
- **求生淨土**：淨土門總本（信願行三事、四十八願、九品）
- **門十四門總說**：四土之總本（同居・方便・實報・寂光，「不必捨身受身。然後證入。故名為橫」）
- **門十五**：本無譜表——**非「不行」而是「無行法」**，已至究竟更無所往
- **卷末紀事**：癸巳五月初三舉筆，二十五日稿成，凡十三日；六月十一日清畢
